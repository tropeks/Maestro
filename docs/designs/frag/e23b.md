## EPICS

Para `docs/architecture/EPICS.md`, dentro do épico E23 ("Prova em vez de palavra"):

- **S-2302 — verificação obrigatória por área + recibo casado com o comando:**
  `.maestro.yaml` ganha `verifications:` (área → `paths` + `labels`) e `commands:`
  (comando canônico por rótulo); `hooks/lib/verifications.sh` (bash+awk, sem yq/Bun)
  responde quais áreas o changeset TOCOU (prefixo de caminho) e que rótulos elas
  exigem. `evidence --record` grava `cmd_match=yes|no|free` e a leitura reprova
  recibo cujo comando não é o declarado (ou cujo `cmd_hash` — sempre gravado, nunca
  comparado até aqui — diverge do declarado hoje): `evidence --record -- true` deixa
  de valer como prova da suíte. `maestro verify [--base REF] [--check]` mostra áreas
  tocadas, rótulos exigidos e o estado de cada recibo. `order --accept` exige, por
  rótulo, recibo com `exit=0`, `wtree_after` == árvore do tip do branch e
  `cmd_match ≠ no`; `outcome accepted` exige recibo VÁLIDA para os rótulos das áreas
  tocadas pelo working tree, e `--unproven` passa carimbando `verifications: missing`.
  Ordem/changeset que não toca área declarada segue exatamente na regra anterior; o
  projeto sem `verifications:` não deve nada. O Maestro dogfooda a regra no próprio
  `.maestro.yaml` (áreas `hooks` e `cli` → rótulo `suite`).
  **Entregue 2026-09-05.**

## DATA_MODEL

### §2 `.maestro.yaml` — emenda E23b/S-2302

```yaml
verifications:                 # área → o que ela exige de quem a tocar
  auth:
    paths: [src/auth/, migrations/]     # prefixos de caminho (git-relativos)
    labels: [suite, tenant-isolation]   # rótulos de recibo (§8) exigidos
  billing:
    paths: src/billing/                 # lista por espaço também vale
    labels: suite
commands:                      # comando canônico por rótulo (opcional)
  suite: bash tests/run-all.sh
```

Parser único em `hooks/lib/verifications.sh` (bash+awk; sem yq, sem Bun, sem jq):
lista em flow (`[a, b]`) ou separada por espaço, **uma linha só**; comentário
` #…` removido; aspas só saem em par (item com aspa solta é descartado — este
parser não suporta valor com espaço). Nome de área `^[a-z0-9][a-z0-9._-]{0,31}$`,
path `^[A-Za-z0-9._/-]{1,80}$`, rótulo com a mesma regra do `--label` do evidence
(`^[a-z][a-z0-9-]{0,23}$`); item fora da regra é descartado em silêncio. **Área sem
path válido é ignorada** (prefixo nenhum casa nada — ela não governa área alguma).
Qualquer chave na coluna 0 fecha o bloco. Config malformada degrada para "nada
exigido"; nunca derruba quem chama.

Áreas TOCADAS = `paths` que casam por **prefixo** com os caminhos do diff. Duas
pontas (`base`..`tip`) para a ordem; com `tip` vazio, working tree + index +
arquivos novos não-ignorados contra a base (default `merge-base main|master HEAD`).
Sem git, sem base ou sem declaração → nada tocado.

### §3 Decision record — emenda E23b (campo `verifications`)

`verifications ∈ {cited, missing}`, opcional, só existe com `outcome` (já validado
no `RECORD_FIELDS`/`record_schema_ok`): `cited` = todos os rótulos exigidos pelas
áreas tocadas tinham recibo VÁLIDA no aceite; `missing` = o aceite passou por
`--unproven`. Changeset que não toca área declarada não grava o campo — ausência
significa "nada era exigido", não "não verificado".

### §8 Ledger de evidência — emenda E23b (linha `cmd_match`)

```
schema=maestro-evidence-v1
…
wtree_before=… / wtree_after=…
cmd_match=yes|no|free
```

`yes` = o comando executado (argv unido por espaço) é idêntico a `commands.<rótulo>`;
`no` = há declaração e o comando difere; `free` = não há declaração. Schema
**continua** `maestro-evidence-v1`: a linha é opcional e o leitor é tolerante —
recibo anterior ao E23b (sem a linha) é lido como `free` e segue valendo.

VÁLIDA passa a exigir também: `cmd_match ≠ no` **e** — quando existe
`commands.<rótulo>` hoje — `cmd_hash` igual aos 16 hex de sha256 do comando
declarado (o hash sempre foi gravado; agora é comparado, o que reprova recibo
velho de outro comando sem precisar de campo novo).

### §9 Work order — emenda E23b

Aceite (`--accept`) exige, além de `provada`, o conjunto de rótulos das áreas que o
branch tocou (`merge-base(main|master, branch)`..`branch`): por rótulo, recibo com
`exit=0`, `wtree_after` == árvore do tip do branch e `cmd_match ≠ no`. Nenhum campo
novo no arquivo da ordem — o estado segue 100% derivado.

## API_SPEC

### `maestro verify` (E23b/S-2302) — NOVO

```
maestro verify [--base REF] [--project P] [--check]
```
- Cruza o diff contra a base (default `merge-base main HEAD`, depois `master`; sem
  git ou sem ancestral → nada tocado) com o bloco `verifications:` do `.maestro.yaml`
  e imprime: a base, as áreas tocadas e, por rótulo exigido, a linha do `evidence`
  (VÁLIDA/VENCIDA/NENHUMA nomeando o motivo e o comando para registrar — com
  `commands.<rótulo>` declarado, o comando REAL, não um placeholder).
- Projeto sem `verifications:` → uma linha dizendo isso, exit 0 (o Maestro não
  inventa dever para quem não o declarou).
- `--base` com ref inexistente → exit 1 (validação). Sem `--check`, é relatório:
  exit 0 mesmo faltando prova. `--check` → exit 1 se algum rótulo exigido não está
  VÁLIDA.
- Log: evento `verify` com `n = <faltantes>`. Nunca rótulo, área ou caminho.

### `maestro evidence` (E13) — emenda E23b
- `--record` grava `cmd_match` (§8) e avisa na hora quando o comando não é o
  declarado. A leitura reprova `cmd_match=no` ("comando diferente do declarado em
  .maestro.yaml") e `cmd_hash` divergente de `commands.<rótulo>`; a linha de VENCIDA
  passa a trazer o comando exato para regravar quando há declaração.

### `maestro order` (E15) — emenda E23b
- `--accept N` recusa (exit 1) quando o branch toca área com verificação obrigatória
  sem o conjunto de recibos exigido, listando `rótulo: NENHUMA|VENCIDA (motivo) —
  <comando para registrar>`. Ordem sem área tocada segue na regra anterior.
- `--status N` ganha a linha `verif   : áreas <…>` + um estado por rótulo exigido.

### `maestro outcome` (E10) — emenda E23b
- `accepted` recusa (exit 1, "sem verificação obrigatória: …") quando o working tree
  contra `merge-base(main, HEAD)` (sem base: contra HEAD) toca área com verificação
  obrigatória sem recibo VÁLIDA; a recusa não fecha o desfecho.
- `--unproven` passa e grava `verifications: "missing"`; caso normal com áreas
  exigidas grava `"cited"`; sem áreas exigidas não grava o campo. `rework`/`reverted`
  nunca são barrados — só o aceite afirma que a entrega serve. O aviso de honra do
  `--suite pass` continua para o rótulo `suite` fora de área exigida.

## CHANGELOG

### Added
- **Mandatory verifications per area (S-2302).** `.maestro.yaml` gains
  `verifications:` (area → `paths` + `labels`) and `commands:` (canonical command per
  label), parsed by `hooks/lib/verifications.sh` — bash + awk, no yq, no Bun, no jq.
  Touched areas come from the diff (path prefix), never from memory.
- **`maestro verify [--base REF] [--project P] [--check]`.** Shows the base, the
  touched areas and, per required label, whether the receipt is VÁLIDA/VENCIDA/NENHUMA
  with the command that produces it. `--check` exits 1 when anything required is
  missing; logs `verify n=<missing>`.

### Changed
- **Receipts now match the declared command.** `evidence --record` writes
  `cmd_match=yes|no|free`; reading rejects `cmd_match=no` and a `cmd_hash` that
  diverges from today's `commands.<label>` — the hash was always recorded, it just was
  never compared. `maestro evidence --record -- true` no longer counts as proof of the
  suite. Schema stays `maestro-evidence-v1`; pre-E23b receipts read as `free` and
  remain valid.
- **`order --accept` refuses without the required set.** Areas touched by
  `merge-base(main, branch)..branch`; each required label needs a receipt with
  `exit=0`, `wtree_after` equal to the branch tip tree and `cmd_match ≠ no`. Orders
  that touch no declared area keep the previous rule. `--status` shows the same
  verdict.
- **`outcome accepted` refuses without the required set.** Areas touched by the
  working tree against `merge-base(main, HEAD)`; `--unproven` passes and stamps
  `verifications: "missing"` in the record (otherwise `"cited"`). `rework`/`reverted`
  are never blocked.
- **Maestro dogfoods the rule:** its own `.maestro.yaml` declares areas `hooks`
  (`hooks/`) and `cli` (`bin/`, `src/`), both requiring `suite`, with
  `commands.suite: bash tests/run-all.sh`.
- `tests/run-all.sh` also enumerates `tests/lib/` (library tests were invisible to the
  runner).
